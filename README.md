# CODE — мобильное приложение (MVP)

Кроссплатформенное мобильное приложение бренда **CODE** — сервиса покупки оригинальной брендовой
одежды, обуви и аксессуаров из аутлетов Южной Кореи со скидками от 30–40%.

Байер находится в Корее, посещает аутлеты и публикует найденные товары в приложении. Покупатели
выбирают размер и оформляют заявку. Наличие товара не гарантировано заранее, поэтому заявка сначала
получает статус «Ожидает подтверждения», а байер подтверждает или отменяет её после проверки.

Это **визуальный прототип (MVP)**: интерфейс полностью рабочий. Каталог, избранное, корзина и
заказы могут храниться в [Supabase](https://supabase.com) (если он подключён — см. раздел
«Бэкенд» ниже) либо работать полностью локально, без какого-либо сервера.

> Репозиторий ранее содержал сайт Samsung Insurance; теперь он полностью отдан под мобильное
> приложение CODE. Состояние репозитория до этого переноса сохранено в ветке
> `backup/samsung-insurance-before-brand-code`.

## Технологии

- [Expo](https://expo.dev) (SDK 57)
- React Native + TypeScript (строгий режим)
- [Expo Router](https://docs.expo.dev/router/introduction/) — файловая маршрутизация
- React Context — состояние приложения (избранное, корзина, заказы, каталог)
- [Supabase](https://supabase.com) (`@supabase/supabase-js`) — опциональный бэкенд: база данных
  и анонимные сессии; без него приложение работает на локальных демо-данных
- `@expo/vector-icons` — иконки
- `react-native-safe-area-context` / `react-native-screens` — безопасные зоны и навигация

Все используемые библиотеки кроссплатформенные и работают на iOS и Android без нативного кода,
что позволяет запускать проект через **Expo Go**.

## Установка и запуск

```bash
# Установка зависимостей
npm install

# Запуск дев-сервера Expo
npx expo start
```

Далее отсканируйте QR-код приложением **Expo Go** на iPhone или Android, либо запустите:

```bash
npx expo start --ios       # симулятор iOS (только macOS)
npx expo start --android   # эмулятор Android
npx expo start --web       # веб-версия для быстрой проверки вёрстки
```

Проверка типов TypeScript:

```bash
npx tsc --noEmit
```

## Бэкенд (Supabase)

Подключение Supabase — **опционально**. Без него приложение работает так же, как раньше: каталог
из `src/data/products.ts`, избранное/корзина/заказы — в памяти, всё сбрасывается при перезапуске.

Чтобы включить настоящий бэкенд:

1. Создайте проект на [supabase.com](https://supabase.com).
2. В **SQL Editor** выполните по очереди `supabase/schema.sql`, затем `supabase/seed.sql`
   (загрузит те же 14 демо-товаров, что и в локальном фолбэке).
3. В **Authentication → Sign In / Providers** включите **Anonymous Sign-Ins** — приложение
   создаёт анонимную сессию на устройстве, чтобы избранное/корзина/заказы сохранялись между
   запусками. Это **не** полноценная авторизация (регистрация/вход по телефону — отдельный,
   ещё не реализованный этап, см. `PROJECT_PLAN.md`), а лишь стабильный идентификатор устройства
   для построчной защиты данных (Row Level Security).
4. Скопируйте `.env.example` в `.env` и заполните значениями из **Project Settings → API**:
   ```
   EXPO_PUBLIC_SUPABASE_URL=...
   EXPO_PUBLIC_SUPABASE_ANON_KEY=...
   ```
5. Перезапустите `npx expo start` (Expo подхватывает `.env` на старте).

Если `.env` отсутствует или переменные не заданы — приложение автоматически работает в локальном
демо-режиме, без ошибок и без сетевых запросов.

```

│   ├── _layout.tsx              # Корневой Stack + провайдеры
│   ├── (tabs)/                  # Нижняя навигация из 5 разделов
│   │   ├── _layout.tsx
│   │   ├── index.tsx            # Главная
│   │   ├── catalog.tsx          # Каталог
│   │   ├── favorites.tsx        # Избранное
│   │   ├── orders.tsx           # Заказы
│   │   └── profile.tsx          # Профиль
│   ├── product/[id].tsx         # Экран товара
│   ├── order-confirmation.tsx   # Модальное окно оформления заявки (быстрый заказ)
│   ├── cart.tsx                 # Корзина
│   └── checkout.tsx             # Оформление заказа из корзины
├── src/
│   ├── types/                   # Типы данных: Product, Order, UserProfile, CartItem
│   ├── data/                    # Демо-данные (локальный фолбэк): товары, заказы, бренды, подписи
│   ├── lib/                     # supabase.ts (клиент), auth.ts (анонимная сессия)
│   ├── services/                # products/favorites/cart/orders — обёртки над Supabase
│   ├── theme/                   # Дизайн-токены: цвета, отступы, типографика
│   ├── utils/                   # Форматирование цены, даты, таймера
│   ├── store/                   # AppStateContext — состояние приложения
│   └── components/              # Переиспользуемые UI-компоненты
├── supabase/
│   ├── schema.sql                # Таблицы, RLS-политики
│   └── seed.sql                  # Демо-каталог (14 товаров)
├── assets/                      # Иконки и сплэш-скрин приложения

├── app.json
├── package.json
├── README.md
└── PROJECT_PLAN.md
```

## Что уже реализовано

- Нижняя навигация из 5 разделов: Главная, Каталог, Избранное, Заказы, Профиль.
- **Главная**: приветствие, переход к поиску, баннер, список брендов, «Новые поступления», «Успей
  заказать», значок корзины со счётчиком.
- **Каталог**: сетка из 2 колонок, поиск, фильтры по бренду/категории/размеру/цене, сортировка.
- **Карточка товара**: премиальный стиль (тень, скругления), индикатор количества фото, быстрое
  добавление в корзину прямо из карточки с выбором размера в шторке.
- **Экран товара**: карусель из нескольких фото, цены и скидка, описание, выбор размера,
  предупреждение о подтверждении наличия байером, этапы доставки, демонстрационный таймер
  актуальности предложения, добавление в избранное и в корзину.
- **Корзина**: список добавленных товаров, изменение количества, удаление, итоговая сумма.
- **Оформление заказа** (из корзины): сводка товаров, демонстрационный адрес доставки,
  подтверждение создаёт по одному заказу «Ожидает подтверждения» на каждую единицу товара.
- **Быстрая заявка** (с экрана товара, в обход корзины): модальное окно подтверждения → заказ
  «Ожидает подтверждения» → появляется в «Заказах». Оплата нигде не производится.
- **Избранное**: сохранение/удаление товаров, состояние пустого списка.
- **Заказы**: список заявок с номером, товаром, размером, ценой, датой и визуальной шкалой статусов
  (Ожидает подтверждения → Выкуплен → На складе в Корее → В пути → Готов к выдаче), а также
  дополнительные статусы «Отменён» и «Нет в наличии».
- **Профиль**: демонстрационные данные пользователя, настройки уведомлений, язык, поддержка, выход.
- 14 демонстрационных товаров (одежда, обувь, сумки, аксессуары) от 7 брендов: Nike, Adidas,
  Ralph Lauren, Tommy Hilfiger, Lacoste, Polo, New Balance.
- Опциональный бэкенд на Supabase: каталог, избранное, корзина и заказы сохраняются между
  запусками через анонимную сессию устройства (см. «Бэкенд (Supabase)» выше); без настройки
  Supabase приложение работает как раньше, на локальных данных.
- Строгая типизация TypeScript без ошибок, поддержка safe area, корректная кнопка «Назад» на Android.

## Что работает на демонстрационных данных

- **Без Supabase**: каталог, избранное, корзина и заказы — локальные mock-данные в памяти
  приложения, всё сбрасывается при перезапуске (как в самой первой версии MVP).
- **С Supabase**: каталог читается из таблицы `products`; избранное, корзина и заказы
  привязаны к анонимной сессии устройства и сохраняются между запусками. Но это всё ещё не
  полноценный бэкенд продукта:
  - авторизации по телефону/email нет — анонимная сессия лишь заменяет React-Context на диск;
  - публикация товаров байером и подтверждение/отмена заказа — по-прежнему делаются вручную
    через SQL Editor или переключением статуса в БД, кабинета байера ещё нет;
  - push-уведомления, реальная оплата и трекинг доставки — не реализованы.

Эти функции — следующие этапы (авторизация, кабинет байера, админ-панель и далее) — см.
`PROJECT_PLAN.md`.

# Ручной чек-лист сквозного сценария

Этот файл — пошаговый сценарий для проверки в **Expo Go** на реальном
устройстве или симуляторе. Автотестов (Detox/Playwright) в проекте пока нет —
для MVP это ручная проверка перед каждым релизом.

> В этой рабочей среде нет ни симулятора/устройства, ни живого проекта
> Supabase, поэтому пункты ниже проверены через чтение кода, `tsc --noEmit` и
> успешную сборку (`expo export`), но не запускались вживую. Перед реальным
> релизом пройдите чек-лист на устройстве самостоятельно — ниже указано, что
> именно проверять на каждом шаге.

## Режим A — без Supabase (`.env` отсутствует)

1. **Каталог → товар**: открыть Каталог, применить фильтр по бренду и по
   размеру, открыть карточку товара из результатов.
   Ожидается: список фильтруется мгновенно, карточка товара открывается с
   каруселью из 3 фото.
2. **Выбор размера**: на экране товара выбрать размер.
   Ожидается: все размеры товара доступны (в локальном режиме сток не
   ограничен).
3. **В корзину**: нажать «В корзину», затем открыть корзину через иконку в
   шапке.
   Ожидается: товар в корзине с выбранным размером и количеством 1.
4. **Checkout**: перейти в оформление заказа, выбрать страну доставки.
   Ожидается: стоимость и срок доставки обновляются при смене страны, итог
   пересчитывается (товары + доставка).
5. **Подтверждение**: подтвердить заказ.
   Ожидается: экран успеха с числом созданных заявок; переход в «Заказы»
   показывает новый заказ со статусом «Ожидает подтверждения», страной и
   стоимостью доставки.
6. **Перезапуск приложения**: закрыть и открыть приложение заново.
   Ожидается (ожидаемое поведение без бэкенда): корзина и избранное пустые,
   в «Заказах» — исходные демо-заказы + всё, что вы создали в этом
   запуске, тоже исчезнет. Это ожидаемо и описано в README как поведение
   локального режима.

## Режим B — с настроенным Supabase

Требует выполненных `supabase/schema.sql` и `supabase/seed.sql`, включённых
Anonymous Sign-Ins и заполненного `.env` (см. README, раздел «Бэкенд»).

1. Повторить шаги 1–5 из режима A.
2. **Персистентность**: полностью закрыть и открыть приложение заново.
   Ожидается: избранное, корзина и созданные заказы **сохранились** —
   анонимная сессия устройства подхватилась заново.
3. **Оverselling**: в Table Editor выставить `product_variants.stock = 0`
   для какого-то размера, затем попробовать оформить заказ на этот размер.
   Ожидается: заявка **не создаётся**, показывается `Alert` с сообщением об
   ошибке (например, «Размер M товара p001 закончился…»), корзина не
   очищается.
4. **Несколько позиций разом**: добавить в корзину 2–3 разных товара и
   оформить заказ одним чеком.
   Ожидается: в базе (`orders`) появляется по одному ряду на каждую единицу
   товара с одинаковым `created_at` (плюс-минус секунда) и последовательными
   `order_number`.
5. **RLS**: попробовать через SQL Editor выполнить `select * from orders`
   от имени анонимного пользователя (Supabase → Authentication → тестовый
   JWT) — должны быть видны только его собственные заказы.

## Адаптивность и состояния

- Проверить Каталог/Избранное/Корзину на маленьком экране (iPhone SE / узкий
  Android, ~360px) — сетка в 2 колонки не должна обрезаться или наезжать.
- Пустое избранное, пустая корзина, пустой список заказов, поиск без
  результатов — везде должен показываться `EmptyState`, а не пустой экран.
- Отключить интернет на устройстве при открытом каталоге (режим Supabase) —
  приложение должно тихо откатиться на локальный демо-каталог, а не
  зависнуть на спиннере (см. `src/services/products.ts`).
- Перейти по несуществующей ссылке (например, deep link на
  `brandcode://unknown`) — должен открыться экран `+not-found.tsx`, а не
  креш.

## Демо-каталог

20 товаров, 7 брендов (Nike, Adidas, Ralph Lauren, Tommy Hilfiger, Lacoste,
Polo, New Balance), все 4 категории (одежда, обувь, сумки, аксессуары) —
достаточно для проверки фильтров по бренду/категории/размеру/цене и
сортировок. Один товар (`p012`) намеренно помечен раскупленным
(`is_available: false`, весь сток в `product_variants` — 0) для проверки
состояния «Раскуплено».
